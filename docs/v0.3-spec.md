# ΘΕΜΙΣ OS — Specification v0.3 (Small-Firm Pivot)

**Version:** v0.3 (2026-05-07)
**Author:** Daedalus (Tier-1 Coding Architect)
**Status:** DRAFT — Pending Niko approval
**Pivot:** Enterprise (20-50 lawyers) --> Small firms (1-15 lawyers, 90% of Greek market)

---

## ADR: v0.2 --> v0.3 Small-Firm Pivot

**Context:** Market research (Herodotos agent, 2026-04-28) validated that 60-65% of Greek lawyers are solo practitioners and 25-28% work in firms of 2-5 lawyers. The v0.2 spec targeted enterprise firms (20-50+) that represent <3% of the Greek market. Building for enterprises first means 9+ months to MVP with EUR 340K budget, targeting a market of ~100-200 firms. The small-firm market is ~22.000+ offices.

**Decision:** Pivot target from enterprise to small firms. Compress scope, cut enterprise-only modules, add solo practitioner features, deliver MVP in ~4 months instead of 9.

**Alternatives considered:**
- Keep v0.2 and target enterprise first: Rejected -- too small a market, too long to revenue.
- Build both simultaneously: Rejected -- resource constraint, diluted focus.

**Consequences:**
- Better: Faster time-to-revenue, larger addressable market, simpler architecture.
- Worse: Enterprise features (ethical walls, multi-department, trust 3-way) deferred. Niko's firm cannot be pilot (too complex).

**Reversibility:** High. Enterprise modules can be added in Phase 2/3 without architectural rework because Unified Party Model and Matter M2M remain unchanged.

## 1. Architectural Invariants (v0.3)

Invariants #1-5 and #7-10 from v0.2 are **UNCHANGED**.

**Invariant #6 REVISED:**

| Tier | Architecture | Rationale |
|------|-------------|-----------|
| STARTER (EUR 19/user/mo) | Shared multi-tenant (row-level `tenant_id`) | Margin impossible with dedicated DB at EUR 19 |
| PROFESSIONAL (EUR 39/user/mo) | Shared multi-tenant (row-level `tenant_id`) | Still insufficient margin for dedicated |
| FIRM (EUR 59/user/mo) | Dedicated single-tenant (per-firm DB) | Sufficient margin, data isolation premium |
| ENTERPRISE (EUR 79+/user/mo) | Dedicated single-tenant + custom SLA | Full isolation |

**Implementation:** Shared-tier tables re-gain `tenant_id` column. Application layer enforces `WHERE tenant_id = :tid` on all queries via Prisma middleware. Dedicated-tier firms keep the v0.2 pattern (no `tenant_id`, isolated DB).

**New Invariant #11 -- Solo Mode:** Every screen and workflow must function with exactly 1 user and 0 departments. No feature may require a second user to operate. "Assign to" defaults to self. Approval chains collapse to self-approval.

## 3. Revised Sprint Plan (v0.3)

### Phase 1: Small-Firm MVP (10 Sprints = 20 Weeks = ~5 Months)

**Target:** Production-ready for 20-50 pilot firms (solo + 2-5 lawyers). ΔΣΘ beachhead launch.

#### Sprint 1-2: Foundation + Multi-Tenant + Mobile Shell (Weeks 1-4)

**Goal:** Scaffold, auth, TWO-TIER tenant provisioning, PWA shell.

**Deliverables:**
- Monorepo (Turborepo): `ui`, `types`, `config`, `validators`, `greek-utils`, `db`, `crypto`
- Next.js 15 App Router, Tailwind, shadcn/ui, mobile-first PWA shell (360/768/1280 breakpoints)
- Service worker for offline cache (hearing list, matter details)
- Fastify API scaffold with plugin architecture, Pino logging
- PostgreSQL schema:
  - **Shared DB:** `tenant`, `user`, `role`, `permission`, `session`, `audit_log` -- all with `tenant_id`
  - **Provisioning logic:** Starter/Professional --> shared DB row creation. Firm/Enterprise --> dedicated DB creation (reuse v0.2 template)
- Prisma middleware: automatic `tenant_id` injection on all shared-tier queries
- JWT auth (login, refresh, logout, MFA stub)
- RBAC with 4 built-in roles: admin, partner, associate, secretary
- Solo Mode: all screens work with 1 user, 0 departments
- Docker Compose (dev: Postgres, Redis, Qdrant)
- GitHub Actions CI (lint, typecheck, test)
- Redis for cache + BullMQ
- Audit log middleware (append-only)
- Landing + Login + Registration pages
- **5-Minute Onboarding Wizard** (firm name, AFM, bar association, first user, subscription tier)

**Acceptance criteria:**
- New firm registration < 5 minutes from zero to dashboard
- PWA installable on iOS Safari + Android Chrome
- Solo mode: entire flow works with 1 user
- Shared-tier tenant isolation: firm A cannot see firm B data (integration test)
- CI green

**Team:** 2 full-stack devs + 0.5 designer

### Multi-Tenant Implementation (Shared Tier)

```typescript
// Prisma middleware for shared multi-tenant
prisma.$use(async (params, next) => {
  const tenantId = getCurrentTenantId(); // from JWT context

  // Inject tenant_id on all creates
  if (params.action === 'create') {
    params.args.data.tenant_id = tenantId;
  }

  // Inject WHERE tenant_id on all reads/updates/deletes
  if (['findMany', 'findFirst', 'findUnique', 'update', 'delete'].includes(params.action)) {
    params.args.where = { ...params.args.where, tenant_id: tenantId };
  }

  return next(params);
});
```

For dedicated-tier firms, this middleware is bypassed (single-tenant DB, no `tenant_id` column needed).
